# Project rules

Read and follow all linked rule files before starting project work. These are mandatory
project instructions, not optional reference material.

- [Branching strategy](docs/rules/branching-strategy.md) — start new features from the
  freshly fetched remote default branch.
- [Subagent collaboration](docs/rules/subagent-collaboration.md) — involve Atlas (Tech Lead)
  and delegate with clear ownership.
- [Graphify](docs/rules/graphify.md) — use the knowledge graph before codebase exploration
  and refresh it after code changes. When the user types `/graphify`, read and apply the
  installed Graphify skill before doing anything else.
- [Spec-driven development](docs/rules/spec-driven-development.md) — follow Spec Kit from
  specification through implementation, governed by the project constitution.
- [Project structure and conventions](docs/rules/project-structure.md) — follow existing
  folder responsibilities, architecture, content, accessibility, and verification conventions.

Explicit user instructions take precedence. The [constitution](.specify/memory/constitution.md)
governs feature intent and quality; these rule files provide operational guidance.
